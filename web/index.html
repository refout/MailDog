Features

把「读邮件」这条路走顺

从实时收信到本地索引，从 HTML 净化到托盘常驻，每个环节都按日常收信的真实路径来设计。

统一收件箱

顶部聚合所有账户的收件箱、已发送、草稿等默认文件夹，下面按账户展开二级文件夹，未读数一目了然。

多账户两级树

IMAP IDLE 实时收信

每个账户维持独立监听连接，新邮件即时到达；断线按 30 秒起、最长 10 分钟的指数退避重连，睡眠唤醒后立即重新同步。

IDLE退避重连

SQLite 本地索引

账户、文件夹、邮件头与正文缓存到本地；已同步过的邮件离线也能翻看，列表与搜索的响应不受网络影响。

HTML 白名单净化

1

UI 按需启动、关闭即退

双击 UI 时若 Engine 未运行会自动拉起；关闭窗口后 UI 与 WebView2 进程全部退出，不留后台渲染进程。

2

Engine 常驻托盘

Engine 是无窗口进程，托盘菜单提供打开 UI、立即同步、退出三项；数据库与日志都在 %LOCALAPPDATA%\MailDog\。

3

连接失败也不静默

IDLE 断线按指数退避重连，周期增量同步作为兜底；睡眠唤醒后自动恢复连接并立即补一次同步。

4

AOT 纪律

全程禁用反射式序列化，IPC 使用源生成 JSON；原生库以嵌入资源随 exe 分发，避免额外的安装步骤。

Get started

三步开始收信

不需要 .NET 运行时，也不需要单独的数据库或服务端组件。

1

下载并安装

安装包会创建开始菜单项与卸载入口；便携版解压后双击 MailDog.UI.exe，两个 exe 需放在同一目录。

2

添加账户

QQ 邮箱在网页端开启 IMAP 后使用授权码登录；Outlook 点击「使用浏览器登录」走 OAuth2 + PKCE，无需填写密码。

3

等第一封邮件

添加成功后自动同步最近邮件并挂起 IDLE 监听；之后收信由托盘进程负责，UI 可以随时关掉。

当前构建未做代码签名，首次运行可能触发 SmartScreen 提示，选择「更多信息 → 仍要运行」即可；Windows 10 需另装 WebView2 Runtime，Windows 11 已内置。

FAQ

常见问题

下载前值得先看一眼的几件事。

需要先安装 .NET 运行时吗？

不需要。UI 与 Engine 都是 Native AOT 单文件，运行时已静态链接进 exe；原生依赖随 exe 分发。

支持哪些邮箱？

目前内置 QQ 邮箱与 Outlook（含 Microsoft 365 个人/工作账户）两条路径。其他标准 IMAP 服务器尚未在界面上开放配置，属于后续版本的范围。

为什么现在只能读、不能写信？

v1 的目标是把收信链路做扎实：同步、索引、净化、通知、托盘。撰写 / 回复 / 转发与 SMTP 发信在 v1.1 排期，代码中暂无半成品入口，避免出现点了没反应的按钮。

邮件和账号信息存在哪里？

全部落在本机 %LOCALAPPDATA%\MailDog\：SQLite 数据库保存账户、文件夹与邮件缓存，日志同目录。没有自建云端服务，数据不出本机。

首次运行提示「Windows 已保护你的电脑」怎么办？

因为构建未购买代码签名证书。点击「更多信息 → 仍要运行」即可；如果你从源码自行构建，也不会看到该提示。签名与自动更新在 v1.1 处理。

arm64 设备能用吗？

可以，提供 win-arm64 便携包，原生构建、无需仿真运行。安装包目前只出 x64，Arm 设备请用便携版解压运行。

遇到问题怎么反馈？

在 GitHub 仓库提 Issue，附上版本号、Windows 版本与 %LOCALAPPDATA%\MailDog\ 下的日志片段，能显著缩短排查时间。
