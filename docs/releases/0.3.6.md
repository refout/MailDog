# MailDog 0.3.6 发布说明

日期：2026-11-26

状态：已发布（v0.3.6，2026-11-26）。

## 这一版做了什么

0.3.6 是界面重构版本，邮件收发、CLI 与发布工程与 0.3.5 保持一致，重点收口主窗口、设置页和 Windows 标题栏。

### 主窗口

- 左、中、右三栏统一为 12px 圆角卡片、1px 描边与 12px 栏间距，阅读区与写邮件覆盖层同步圆角。
- 左栏底部固定设置入口，不再贴住窗口边缘或被裁切。
- 折叠阈值、列宽动画与拖动逻辑保持 0.3.5 行为。

### 设置页

- 设置页壳层改为 232px 导航 + 840px 内容宽度，内容整体居中。
- 11 个设置页统一标题与说明层级，27 个设置组收进卡片。
- 修复账户列表的 XML 层级泄漏：账户页之前会把账户列表带到其他设置页。
- 账户页按「邮箱账户 → 账户签名 → 发信别名 → 默认签名」重排，与设置项的先后关系一致。

### Windows 标题栏

- 使用 Avalonia 12 的 `WindowDecorations="Full"` 与 `ExtendClientAreaToDecorationsHint="True"` 延展客户区。
- 自绘 32px 透明标题条，保留系统最小化、最大化、关闭按钮，标题条只放 MailDog 品牌。
- `TitleBarBackgroundBrush` 覆盖为透明，Mica/Acrylic 可以贯穿标题条；默认标题文字与全屏按钮已隐藏，避免和品牌文字重复。
- 标题条用 `WindowDecorationProperties.ElementRole="TitleBar"` 标记拖动命中区，品牌内容不拦截拖动。
- 非 Windows 平台隐藏自绘标题条并把标题行高度置 0，关闭客户区延展，Linux/macOS 继续使用系统标题栏。

### 材质链路

- 修复 Mica/Acrylic 启用时承载文字的表面被补成不透明的问题，按背景透明度重算 Surface 系列。
- Windows 11 才启用 Mica，Windows 10 1809+ 才启用 Acrylic；已保存但当前系统不可用的材质回退为纯色。

## 验证结果

```powershell
dotnet build src\MailDog.slnx -c Release -p:OS=Windows_NT -p:EnableWindowsTargeting=true --nologo
dotnet test src\MailDog.slnx -c Release --no-build --nologo
```

- 构建 0 警告 0 错误。
- 187 项测试通过：Html 31、Contracts 23、Cli 27、UI 38、Mail 68。
- Windows 11 实机截图确认主窗口圆角、底部设置入口、透明标题条和 caption 按钮对齐。
- 标题栏按钮点击、拖动与双击最大化未纳入本轮自动化验收，只做了视觉检查和代码路径检查；发布后仍需在干净的 Windows 用户上复核。

## 已知限制

- 受信任 OV/EV 代码签名证书尚未提供；未配置 secrets 时 Windows 产物仍为未签名。
- 正式崩溃上报端点尚未提供；默认关闭，不会联网。
- 本机没有 MSVC/C++ Build Tools，Windows Native AOT 产物由 GitHub Actions `windows-latest` 构建。
- Linux 真实桌面托盘、通知点击与 WebKitGTK 仍未验收；WSLg 只覆盖 X11 窗口启动。
