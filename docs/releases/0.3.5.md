# MailDog 0.3.5 发布说明

日期：2026-11-26

状态：已发布（v0.3.5，2026-11-26）。

## 这一版做了什么

0.3.5 是发布工程版本，邮件功能与 0.3.4 保持一致，主要把 Windows/Linux 分发链路补齐。

### 代码签名

- 新增 `src/build/sign.ps1`：支持 PFX 文件，也支持从 `MAILDOG_SIGN_PFX_BASE64` 读取；密码从 `MAILDOG_SIGN_PFX_PASSWORD` 读取。
- 可签单个 exe 或目录；目录自动签 `MailDog.Engine.exe`、`MailDog.UI.exe`、`MailDog.Cli.exe`。
- 优先使用 `signtool.exe`，找不到时回退 PowerShell `Set-AuthenticodeSignature`。
- 默认 RFC 3161 时间戳 `https://timestamp.digicert.com`，可由 `MAILDOG_SIGN_TIMESTAMP_URL` 覆盖。
- `package.ps1` 在 Windows、且存在 `MAILDOG_SIGN_PFX_BASE64` 时，于压缩打包和生成安装包之前签名。
- `.github/workflows/release.yml` 已接入 `MAILDOG_SIGN_PFX_BASE64`、`MAILDOG_SIGN_PFX_PASSWORD` 与 `MAILDOG_SIGN_TIMESTAMP_URL`。
- 没有配置 PFX 时跳过签名，产物仍可构建和发布；配置了 PFX 但签名失败会终止。

### 崩溃上报

- UI 未处理异常仍写本地 `crash.log`，不改变原有排查方式。
- 配置 `MAILDOG_CRASH_ENDPOINT` 或 `%LOCALAPPDATA%\MailDog\crash-endpoint.txt` 后，额外异步 POST 一份崩溃摘要。
- 只接受 `https`，或本机 `http://localhost` / `127.0.0.1` / `[::1]`。
- 发送失败写入 `crash-pending/`，下次启动按时间顺序重试，成功一个删一个。
- 上报字段只有 `app/version/time/kind/exception/stack`，**不含异常消息**，避免带出邮件地址、主题或正文。
- 默认不联网；没有端点时行为与之前一致。

### 验收补齐

- Windows 安装包在 XIZXI 干净用户上实测 0.3.4 安装、卸载、0.3.3 安装、0.3.4 覆盖升级、最终卸载全部通过；安装目录与邮件客户端注册项清理正确，用户数据库保留。
- Outlook 真实邮件上通过 UI 点击「标记垃圾邮件并拦截发件人」：邮件移入 Junk，规则落库；同发件人新邮件到达后自动进入 Junk。
- `List-Unsubscribe` 的 https / mailto / One-Click 解析由单元测试覆盖；未向第三方提交退订请求。

### Linux WSLg 启动

- 在 HOME 的 WSL Ubuntu 24.04 + WSLg 中运行 0.3.4 `linux-x64` 包：`MailDog.Engine --probe` 返回 `sqlite: ok`、`mime+imap: ok`；`MailDog.UI` 打开 1280×800 窗口，首次启动显示「添加你的第一个邮箱账户」。
- 关闭 UI 后 Engine 继续驻留；包内 CLI 的 `accounts`、`quit` 可用。
- WSL 最小环境没有中文字体，首次启动中文显示为方框；安装 `fonts-noto-cjk` 后正常。普通 Ubuntu 桌面通常已带字体。
- **0.3.4 暴露两个发布问题**：Linux AOT 下 `Environment.SpecialFolder.LocalApplicationData` 返回空，数据库落到启动目录下的 `MailDog/`；包内 CLI 的 schema 缺 `open`。0.3.5 已把数据目录固定到 `$XDG_DATA_HOME` 或 `$HOME/.local/share`，并给 Linux/Windows 打包脚本加了 CLI `open` 校验。
- WSLg 未安装 WebKitGTK、无通知守护进程与 StatusNotifier 宿主，本轮不把托盘、通知点击、HTML 正文算作通过；仍需真实 Linux 桌面验收。
- 2026-11-26 在 Ubuntu 22.04 云主机（.NET 11 SDK + clang）构建出 `MailDog-0.3.5-linux-x64.tar.gz`，SHA-256 `781125ed5623663458eab4961ccb293c77e844b42ad2ce59cb12f1cd9600638c`。
- 0.3.5 包在 WSLg 复测：UI 1280×800 正常启动；关闭 UI 后 `maildog open` 返回 `{"opened":true}` 并重新拉起窗口；`maildog quit` 返回 `{"stopped":true}`。CLI 不指定 `--engine` 也能从 `cli/` 子目录找到上级 Engine。
- 0.3.5 包的数据目录落在 `~/.local/share/MailDog/maildog.db`，日志、native 库、outbox 同在该目录；设置 `XDG_DATA_HOME` 后改落到 `$XDG_DATA_HOME/MailDog/`。
- Linux 构建还暴露出 0.3.5 `--register-integration` 未加平台条件，导致 Linux 编译找不到 `WindowsIntegration`；已用 `#if MAILDOG_WINDOWS` 隔离，Windows 回归测试仍全绿。

## 验证结果

```powershell
dotnet build src\MailDog.slnx -c Release -p:OS=Windows_NT -p:EnableWindowsTargeting=true --nologo
dotnet test src\MailDog.slnx -c Release --no-build --nologo
```

- 构建 0 警告 0 错误。
- 187 项测试通过：Html 31、Contracts 23、Cli 27、UI 38、Mail 68。
- 自签 PFX 签名 `MailDog.Engine.exe`、`MailDog.UI.exe`、`MailDog.Cli.exe` 成功；`Get-AuthenticodeSignature` 的 `UnknownError` 是自签根不受信任的预期结果，`SignerCertificate` 正确。
- 用自签 PFX 走完整 `package.ps1 -Version 0.3.0 -Runtime win-x64 -SkipPublish -Installer`，zip 与 setup 均生成，退出码 0。
- GitHub Release `v0.3.5` 已发布，四个运行时包与 `MailDog-0.3.5-win-x64-setup.exe` 均已生成；win-arm64 首次因 x64 runner 无法执行 ARM64 CLI 导致打包校验失败，修复为跨架构时校验 `Schema.cs` 后重跑通过。

## 已知限制

- 受信任 OV/EV 代码签名证书尚未提供；未配置 secrets 时 0.3.5 产物为未签名。
- 正式崩溃上报端点尚未提供；默认关闭，不会联网。
- 本机没有 MSVC/C++ Build Tools，0.3.5 的 Windows Native AOT 产物需由 GitHub Actions `windows-latest` 或具备 Build Tools 的机器构建。
- Linux x64 AOT 已由云主机手工构建并在 WSLg 复核；linux-arm64 仍需 CI 的 ARM64 runner 产出。
- Gmail、自定义 IMAP/SMTP 真实账户与 Linux 真实桌面托盘/通知/WebKitGTK 仍未验收；WSLg 只验证了 X11 窗口启动与无托盘 `quit`。
- 0.3.4 包的 Linux 数据目录与 CLI `open` 问题仅存在于已发布产物；0.3.5 源码已修复，手工 linux-x64 AOT 包已复核数据落在 `~/.local/share/MailDog/` 且 `maildog open` 可用，CI 产物仍需按同一清单复核。
