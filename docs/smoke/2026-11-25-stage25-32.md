## 人工交互验收清单

1. 设置 → 账户 → 发信身份：新增一个已在服务商验证的别名，保存后重启 UI，确认别名仍在。
2. 写信：发件人行切换账户与别名，确认签名按「别名 → 账户 → 全局」回退；收件人只填自己另一个邮箱，实际投递后检查 Header `From` 与信封发件人。
3. 保存别名草稿 → 从草稿箱续写，确认身份仍为别名；再用未配置地址调用发信，确认被引擎拒绝。
4. 含 3 个以上附件的邮件：全选、取消全选、保存所选、保存全部；确认重名文件生成 `(1)`、`(2)` 且不覆盖。
5. 选中附件后拖到桌面/资源管理器，确认文件落地；再测试“拖出”单附件把手。
6. 服务商限制：若服务器不允许该别名作为 `From`，投递会被拒，这是服务端授权问题，不是客户端绕过。

## 已知边界

- SMTP 信封发件人固定为账户主邮箱，别名只改 Header `From`，以降低 SPF/DMARC 拒绝概率；服务商仍需允许该别名。
- 附件拖出会先把文件落到 `%LOCALAPPDATA%\MailDog\attachments` 再发起拖放，大附件首次拖出会有下载等待。
- 本记录未执行 NativeAOT 发布产物冒烟；发布前仍需按 `docs/PLAN.md` 的质量门补跑。
