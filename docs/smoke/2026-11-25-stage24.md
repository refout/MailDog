## 真实账户实机（2026-11-26，HOME）

- 使用 3 个已配置真实账户：QQ 1 个（密码登录）、Outlook OAuth2 2 个。
- 为避免污染日常邮箱库，先把 `maildog.db` 通过 SQLite backup 复制到 `%TEMP%\maildog-live-account-test`，再用 `MailDog.Engine.exe --db <副本>` 启动当前构建；UI 与 CLI 都连同一 Engine。
- 结果：
  - 3 个账户登录正常，文件夹角色正确；QQ 收件箱、已发送、草稿、垃圾箱、已删除均识别，Outlook 额外文件夹保留为 Other。
  - 3 个账户各自向本人发纯文本邮件并到达；Outlook 首次正文按需拉取，QQ 命中本地缓存。
  - QQ 发送中文附件名 `验收附件-中文文件名.txt`，重新下载后文件名和 SHA-256 与源文件一致。
  - QQ 草稿保存后重启 Engine 仍存在；定时 3 分钟发送在重启后按点发出；5 分钟定时邮件 `cancel` 返回 `affected=1`。
  - 搜索：QQ 主题/发件人/正文各一次，Outlook 主题一次。
  - UI 通过 `maildog open` 关闭后重新拉起，账号与未读状态来自同一 Engine。
- 发现并修复：
  - Outlook 已发送副本重复：服务器自动保存 + 客户端 APPEND 导致两条。`SmtpSendService.ShouldUploadSentCopy` 对 Outlook 跳过 APPEND；两个 Outlook 账户修复后各复测一封，均只剩一条已发送副本。

## 风险

- 假 IMAP 只覆盖首屏同步路径，不覆盖 IDLE、APPEND、STORE、多文件夹层级和服务端异常。
- 自签证书测试不能证明真实证书链校验正确。
- JumpList 测试写入一条指向 `messageId=900001` 的测试快捷方式，未清理；真实用户环境重跑会替换旧测试链接。
- schema 升级前已有自动快照，但没有“一键恢复”入口；回滚仍需退出 MailDog 后手工替换数据库文件，且旧版必须支持快照的 schema 版本。
