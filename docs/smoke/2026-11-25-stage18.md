# 阶段 18 验收：定时发送与稍后提醒（2026-11-25）

## 范围

- 指定时间发信：`SendMailRequest.ScheduledAtUtc`，UI 写信页可选“1 小时后 / 今晚 20:00 / 明天 08:00 / 自定义时间”，CLI 使用 `send --send-at "2026-11-26 08:30"`。
- 发件箱排队：计划时间与账户撤销窗口取较晚者写入 `OutboxRecord.NextAttemptUtc`；计划邮件显示为“计划发送”，不会被误认为失败重试。
- 稍后提醒：`SnoozeMessageRequest` 写入 `snoozed_messages`，列表 / 搜索 / 文件夹计数立即隐藏并排除未读数；Engine 每 30 秒唤醒到期项，恢复未读并广播 `MailChangedEvent`。
- 选择性重试：沿用发件箱窗口的单项重试，不自动重发已成功邮件。
- CLI：新增 `snooze <邮件 id> --until ... --confirm`；`send` 新增 `--send-at`；写命令白名单加入 `snooze`。
- 数据库迁移：schema 版本 13，新增 `snoozed_messages` 与 `ix_snoozed_until`。

隔离 `LOCALAPPDATA` 后运行：

- `maildog schema --json`：`send` 包含 `--send-at`，新增 `snooze` 命令并包含 `--until`，写命令说明包含 `snooze`。

## 未覆盖与风险

- UI 已通过 Avalonia 编译；HOME 会话不能显示窗口，未在可交互桌面点击写信页时间选择与主窗口“稍后提醒”菜单。
- 计划发送依赖 Engine 常驻；Engine 退出期间不会发信，重启后 OutboxWorker 会按 `NextAttemptUtc` 继续。
- 稍后提醒只改本地 `Seen` 位；服务端同步若把邮件标为已读，到期后本地仍会先变未读，但下一轮同步可能再次跟随服务端状态。要彻底避免，需要在唤醒时回写 IMAP `\Unseen`，本阶段未做。
