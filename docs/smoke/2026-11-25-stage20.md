# 阶段 20 验收：大邮箱与存储（2026-11-25）

## 范围

- 未缓存正文按需拉取：沿用已有 `GetMessageBody` 流程，列表只保存摘要；打开邮件时才从 IMAP 拉取正文，并写入 `bodies` 与 FTS。
- 后台补全文索引：Engine 启动时执行 `SqliteStore.BackfillSearchIndex`，把 `messages` 中缺失于 `message_fts` 的行补齐；异常退出或升级后自动修复。
- 附件缓存配额：拖出附件仍落在本地缓存目录；超过 512 MB 时按最后写入时间淘汰旧文件，刚拖出的文件受保护。
- 数据库压缩：存储清理页新增“压缩数据库”，执行 `PRAGMA wal_checkpoint(TRUNCATE)` 与 `VACUUM`，回收已删除邮件的空洞；结果返回释放字节数。

## 未覆盖与风险

- 512 MB 配额目前是固定值，没有做设置页可调；需要时可后续加 `AttachmentCacheLimitMB`。
- `VACUUM` 会短暂锁住数据库；Engine 会阻塞其他读写，但不会丢数据。UI 已用 `IsStorageBusy` 禁用重复操作。
- 后台补索引只补 FTS 行，不主动联网拉取未缓存正文；全文搜索仍只覆盖已下载正文，和“按需拉取”策略一致。
