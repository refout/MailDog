# 阶段 23 验收：平台扩展

日期：2026-11-25

## 已完成

- Linux arm64 进入发布矩阵：`package-linux.sh linux-arm64` 仅允许在原生 `aarch64` 主机运行；release 流水线新增 `ubuntu-24.04-arm`。
- `linux-arm64` 与 `linux-x64` 共用同一打包结构，产物为 `dist/MailDog-<版本>-linux-arm64.tar.gz`。
- Linux 托盘创建改为可失败：桌面没有 StatusNotifier 宿主时 `LinuxTray` 返回不可用，不再阻止 UI 启动。
- 新增 CLI `maildog open`：通过 Engine IPC `openUi` 叫回主窗口；Engine 在 UI 已连接时广播 `showMainWindow`，未连接时按既有逻辑拉起 UI。
- 设置页“后台进程”说明补充 `maildog open` / `maildog quit`。
- macOS 评估结论写入 `docs/platform-evaluation.md`：暂不发布，待真实需求出现再评估。

dotnet test src\MailDog.slnx -c Release --no-build --nologo

结果：构建 0 警告 0 错误；169 项测试通过（Html 31、Contracts 18、Cli 27、UI 31、Mail 62）。

新增 `OpenUiIsForwardedToEngine`：Fake Engine 收到 `openUi` 并返回 Ok，CLI 命令返回 0。

## 手工验收清单

1. 在 `ubuntu-24.04-arm` 上执行 `./src/build/package-linux.sh linux-arm64`，确认 tar.gz 内含三个可执行文件与两个 `.so`。
2. 在 ARM64 桌面运行 `MailDog.UI`，确认登录、收信、正文渲染和通知。
3. 在没有 StatusNotifier 托盘的桌面运行 UI，确认 UI 正常启动、不崩溃。
4. 关闭 UI 后执行 `maildog open`，确认主窗口重新出现；执行 `maildog quit`，确认 Engine 正常退出。
5. 在 KDE 或带托盘扩展的 GNOME 上确认托盘菜单仍可用。
6. macOS 不进行构建；评估结论保持 `docs/platform-evaluation.md`。
